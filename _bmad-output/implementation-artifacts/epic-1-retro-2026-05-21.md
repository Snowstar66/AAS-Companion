# Epic 1 Retrospective: Control Mirror MVP

Date: 2026-05-21
Project: AAS-Companion
Epic: Control Mirror MVP
Status: completed

## Executive Summary

Epic 1 delivered a usable Control Mirror MVP across snapshotting, artifact manifest, AAS normalization, conformance checks, Value Spine coverage, Human Review recommendations, guardrails and report preview.

The strongest outcome is that Control Mirror now behaves as a deterministic control subsystem rather than a presentation-only dashboard. The main remaining risk is that some MVP integrations are intentionally linked/recommended rather than first-class persisted workflow objects.

## What Worked

- The role-based BMAD handoffs gave enough structure to implement without re-opening product questions during development.
- Keeping core Control Mirror logic in `packages/domain/src/control-mirror.ts` made the behavior testable and kept React components mostly presentational.
- Starting with `current_imports` as the first source mode avoided unsafe assumptions about browser filesystem access, Git roots or uploaded zip extraction.
- Persisting snapshots/artifacts/normalized evidence first gave later stories stable inputs for conformance, test coverage and report generation.
- Focused tests caught practical regressions: widened TypeScript literals, duplicated UI text assumptions and overly permissive guardrail logic.

## What Was Hard

- The feature reference is broader than a single MVP epic. Several requirements needed careful slicing to avoid implementing a large platform in one pass.
- Human Review has an existing tollgate/signoff model but no general-purpose first-class queue model for Control Mirror findings. The MVP therefore links review recommendations into `/review` instead of creating a new persisted Human Review table.
- Guardrail language is business-critical. The post-implementation QA found that `riskProfile` was too broad to count as AI Risk Ledger evidence, which would have weakened the control claim.
- The UI now repeats some terms in multiple places by design, which made brittle single-element page assertions less useful.

## Key Lessons

1. Higher AI-level claims need stricter evidence semantics than general project risk fields.
2. Report preview data should be generated from the same deterministic dashboard model to prevent drift between screen and report.
3. Linked Human Review items are acceptable for MVP, but persisted review lifecycle will become important once people need decisions, audit history and ownership.
4. Source modes should remain explicit and user-authorized. Browser-local or repository scanning must not be assumed.
5. Tests should assert user-visible capability rather than uniqueness of repeated dashboard labels.

## Quality And Readiness Assessment

Testing and quality: Green for focused MVP coverage and production build.

Deployment readiness: Code builds successfully. Local DB schema was synced for schema-changing stories.

Stakeholder acceptance: Not formally recorded in this run. Product/mandate acceptance should be treated as a follow-up before claiming Control Mirror as production governance.

Technical health: Stable enough for MVP continuation. The domain file is now large and should be monitored before adding more conformance families.

Known residual risks:

- Human Review recommendations are linked, not fully persisted as a dedicated review queue.
- Parsing remains deterministic and filename/content-pattern based, not deep semantic extraction.
- Uploaded zip, folder snapshot, Git connector and real-time watching remain out of sprint.
- Full content retention/redaction policy is not implemented for broad log evidence.
- The readiness report artifact still shows an initialization status even though the run proceeded with handoffs in place; future BMAD tracking should keep readiness artifacts fully synchronized.

## Next Epic Preparation

No Epic 2 is currently defined in sprint tracking.

Before starting the next epic, prepare one of these paths:

- Control Mirror workflow hardening: persisted Human Review queue, decision lifecycle and audit history.
- Source ingestion expansion: uploaded zip or folder snapshot with path traversal protection and retention rules.
- Evidence parsing expansion: richer parser/normalizer modules and source excerpt policy.
- Report/export expansion: durable Control Mirror report artifacts and evidence pack export.

Recommended starting point: decide the next product path before creating new stories, because each path has different data-model and security implications.

## Retrospective Outcome

Epic 1 is complete from a story and build-verification perspective. The next planning move should be deliberate rather than automatic: choose whether Control Mirror should deepen governance workflow, source ingestion, parsing fidelity or report/export capability next.
