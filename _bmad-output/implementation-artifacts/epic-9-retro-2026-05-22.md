# Epic 9 Retrospective: Product/Security Acceptance

Date: 2026-05-22
Project: AAS-Companion
Epic: Product/Security Acceptance
Status: completed

## Sammanfattning

Epic 9 gjorde Control Mirror evidence pack-exporter tydliga som genererade audit artifacts, inte automatiskt godkända governance- eller externa delningsartefakter. Evidence pack-payload och Markdown innehåller nu Product/Security acceptance posture, Control Mirror visar acceptanskrav och exporthistoriken kan registrera senaste mänskliga acceptance decision per export.

Det viktigaste resultatet är att persisted exports nu bär sin egen delningsvarning även vid re-download, inklusive legacy-records som saknade acceptance-fält när de skapades.

## Slutförda Stories

- Story 9.1: Add Evidence Pack Product/Security Acceptance Policy
- Story 9.2: Record Export Acceptance Decisions
- Story 9.3: Gate External Sharing Copy on Acceptance
- Story 9.4: Harden Acceptance Regression Coverage and Retro

## Vad Som Fungerade

- Acceptance-policy lades i domain-lagret, vilket gjorde JSON, Markdown, UI och persisted re-download konsekventa.
- Beslutsmodellen blev event-baserad och tenant-scoped utan att mutera den ursprungliga evidence pack-payloaden.
- Latest-decision-selecten höll historiklistan lätt; UI behöver inte läsa full export-body för att visa acceptance state.
- Legacy-enrichment vid download skyddar äldre persisted exports utan datamigration eller rewrite av payload.
- Samlad regression över payload, Markdown, route, service, repository och page gav bra signal innan epicen stängdes.

## Vad Som Var Svårt

- Prisma indexnamn blev för långa när acceptance decision-modellen lades till; explicita `map`-namn löste det.
- Runtime package build behövs före web-tester när nya exports från `@aas-companion/db`, `@aas-companion/domain` eller `@aas-companion/api` används.
- UI-testmockar behöver uppdateras när server actions läggs till; annars faller page-testet innan användarflödet testas.
- Regressionen fångade en verklig språkbugg: singular-copy för `1 sensitive finding` behövde `requires`.

## Lärdomar

1. Acceptance och sharing posture bör följa artefakten, inte bara sidan som genererade den.
2. Beslut om acceptans ska vara separata audit events; exportens bevisinnehåll ska förbli stabilt.
3. Download-pathen behöver skydda gamla records när policyformatet utvecklas.
4. Product/Security-copy är testbar domänlogik, inte bara UI-text.
5. Exportregressionen bör fortsätta köras som en sammanhållen gate efter schema- eller policyändringar.

## Readiness Assessment

Testing and quality: Grönt för acceptance payload, Markdown rendering, export create/download routes, legacy download enrichment, persisted decision recording och Control Mirror page state.

Deployment readiness: Kräver DB-migrationerna för Epic 8 och 9 i målmiljö:

- `20260522103500_control_mirror_evidence_pack_exports`
- `20260522111500_control_mirror_export_acceptance_decisions`

Technical health: Bättre än före Epic 9. Acceptance posture är centraliserad i domain och download service skyddar äldre records. Beslutsmodellen är scoped och event-baserad.

Residual risk:

- Ingen rollbaserad behörighetsmodell skiljer ännu Product owner, Security/privacy och AQA i server action.
- Ingen full acceptance lifecycle finns ännu för ändring, revoke, supersede eller flera required approvals.
- Re-download-händelser audit-loggas inte separat.
- Exporthistorik saknar fortfarande retention/archive/delete-policy.
- Befintliga React/Next/webpack-varningar skapar fortsatt brus i verifiering.

## Rekommenderad Nästa Väg

Rekommenderad nästa epic är **Export Acceptance Workflow Hardening** om målet är release-readiness: rollkontroller, multi-role approval gate, revoke/supersede och tydligare “shareable only when required roles accepted”.

Alternativt är **Export Retention Governance** rätt väg om nästa risk är drift: archive/delete-policy, retention windows och re-download audit events.

## Retro Outcome

Epic 9 är komplett från story-, test- och build-perspektiv. Control Mirror evidence packs har nu explicit Product/Security acceptance posture, persisted acceptance decision history och fail-safe sharing copy på både historik och re-download.
