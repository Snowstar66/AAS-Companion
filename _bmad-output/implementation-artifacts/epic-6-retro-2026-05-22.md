# Epic 6 Retrospective: Report and Evidence Pack Export

Date: 2026-05-22
Project: AAS-Companion
Epic: Report and Evidence Pack Export
Status: completed

## Executive Summary

Epic 6 turned Control Mirror's report output into a portable evidence pack. The system now has a domain-owned export payload, a protected JSON download route, UI guidance about what is included, and regression tests that protect against raw source text leakage and lost Human Review decisions.

The strongest outcome is that Control Mirror is no longer only an on-screen dashboard. It now has a shareable audit artifact that preserves source/snapshot metadata, report summary, evidence summaries, findings, Human Review state and retention disclosure.

Existing non-blocking warnings remain:

## What Worked

- Epic 5's report module made the export model straightforward to add without scraping UI.
- The protected route kept export behavior simple and project-scoped.
- The export payload explicitly includes safety disclosure and excludes raw source text.
- Page guidance now tells users what the evidence pack includes before download.
- Regression tests cover both payload safety and UI failure copy.

## What Was Hard

- `exactOptionalPropertyTypes` caught a real optional-parameter issue in the API service.
- Page tests are currently not auto-isolated between renders, so repeated UI assertions need `getAllBy*` patterns.
- Exporting JSON through a route is clean, but route-level tests are still not present.

## Key Lessons

1. A stable domain export model should come before download UI.
2. Evidence pack safety needs explicit negative assertions around raw content fields.
3. Human Review decisions are part of auditability, not just dashboard state.
4. Export guidance belongs near the download action, not buried in report detail.

## Quality And Readiness Assessment

Testing and quality: Green for targeted export/domain/page coverage and production build.

Deployment readiness: Code builds successfully. No schema changes were introduced.

Technical health: Good. Export logic now lives in the report domain module, API service and protected route with clear UI affordance.

Known residual risks:

- There are no direct route handler tests for `/control-mirror/export` yet.
- Export format is JSON only; Markdown/PDF/human-readable packs are not implemented.
- Export artifacts are generated on demand and not persisted.
- Existing build/test warnings remain noisy.
- Formal product/security acceptance is not captured.
