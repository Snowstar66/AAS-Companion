# Epic 11 Retrospective: Export Retention Governance

Date: 2026-05-22
Project: AAS-Companion
Epic: Export Retention Governance
Status: completed

## Sammanfattning

Epic 11 gjorde persisted Control Mirror evidence pack exports governable over time. Exporthistoriken har nu retention state och policy label, aktiva exports kan arkiveras med actor/timestamp/reason utan att payloaden tas bort, och lyckade re-downloads audit-loggas med human actor.

Det viktigaste resultatet är att sparade audit artifacts inte längre bara är filer i historiken. De har en enkel lifecycle: active, archived, downloadable with disclosure, and traceable access history.

## Vad Som Fungerade

- Retention metadata kunde läggas på export records utan att ändra persisted download body, filename eller content type.
- Archive som state mutation, inte delete, bevarar audit artifact och acceptance history.
- Archive disclosure headers gör archived downloads tydliga utan att blockera governance/audit åtkomst.
- Re-download audit events blev en separat append-only tabell, vilket håller access traceability åtskild från export payload.
- Route-level fail-closed audit är rätt gräns: om audit event inte kan skrivas serveras inte filen.

## Vad Som Var Svårt

- Export history samlar nu retention, archive, acceptance readiness och latest download metadata i samma tabellvy; den börjar bli informationsrik och behöver snart mer UX-prioritering.
- Full testsvitens äldre fel gör det svårt att använda `pnpm test` som ren epic-gate.
- Prisma schema och runtime package builds behöver köras i rätt ordning efter varje schemaändring.
- Server action authority för archive är fortfarande baserad på aktiv membership role, inte en full Party Role Directory assignment.

## Lärdomar

1. Persisted audit artifacts ska behandlas som records med lifecycle, inte bara downloadable files.
2. Archive/delete/restore ska hållas isär. Archive är säkert som första governance-steg eftersom historik och payload bevaras.
3. Access audit ska vara append-only och fail-closed på download route.
4. Export history list-selects måste fortsätta vara metadata-only; payload bodies hör bara hemma i explicit download path.
5. Regressionerna bör grupperas runt lifecycle-stegen: create/list metadata, archive action, archived download, download audit, history display.

## Readiness Assessment

Testing and quality: Grönt för Epic 11 targeted regression: repository, API, server action, route och page coverage.

Deployment readiness: Kräver DB-migrationerna från Epic 8-11 i målmiljö, särskilt:

- `20260522103500_control_mirror_evidence_pack_exports`
- `20260522111500_control_mirror_export_acceptance_decisions`
- `20260522124500_control_mirror_acceptance_revoked_decision`
- `20260522132000_control_mirror_export_retention_state`
- `20260522140500_control_mirror_export_download_events`

Technical health: Bättre än före Epic 11. Export governance är nu tenant-scoped, metadata-visible, archive-safe and access-audited.

Residual risk:

- No retention window, legal hold, expiry or delete policy exists yet.
- Archive authority is role-gated but not tied to Party Role Directory assignments.
- Latest download display shows actor id, not a resolved human name.
- Full test suite still has unrelated failures, so release gates need either targeted gating or cleanup.
- UI density in export history is increasing and may need a dedicated details view.
