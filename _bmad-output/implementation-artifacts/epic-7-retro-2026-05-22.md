# Epic 7 Retrospective: Evidence Pack Route and Format Hardening

Date: 2026-05-22
Project: AAS-Companion
Epic: Evidence Pack Route and Format Hardening
Status: completed

## Sammanfattning

Epic 7 gjorde Control Mirror-exporten tryggare att utveckla vidare. JSON-exporten har nu direkta route-tester, Markdown-export finns som läsbart alternativ, filnamn byggs via en delad domain-helper och exportmetadata är låst med regressionstester.

Det viktigaste resultatet är att evidenspaketet inte längre bara är en JSON-route. Det har ett testat route-kontrakt, ett mänskligt läsbart format och stabila formatdetaljer för audit-spårbarhet.

## Slutförda Stories

- Story 7.1: Add Evidence Pack Export Route Tests
- Story 7.2: Add Markdown Evidence Pack Export Format
- Story 7.3: Harden Export Filename and Version Metadata
- Story 7.4: Harden Export Regression Coverage and Retro

## Vad Som Fungerade

- Route-kontraktet var litet och lätt att testa direkt med mockad session och API-service.
- Domain-ägd exportmodell gjorde Markdown-serialisering möjlig utan att läsa från UI.
- Negativa assertions runt rå källtext fortsätter skydda exporterna.
- Delad filnamns-helper minskar risken att JSON och Markdown divergerar.
- Samlad export-regression gav snabb signal över payload, route och page-disclosure.

## Vad Som Var Svårt

- Testfixtures för routen behövde vara tillräckligt kompletta för att även fungera genom Markdown-buildern.
- Exportformaten började skapa små dupliceringsrisker i route-logik, vilket motiverade filnamns-helpern.
- Den återkommande Vitest-sandbox-begränsningen gör lokala gröna testkörningar mer bullriga än själva kodändringen.

## Lärdomar

1. Exportformat ska dela metadata- och filnamnslogik tidigt.
2. Route-tester bör låsa både happy path och fail-closed behavior för audit-flöden.
3. Markdown är mest värdefullt när det byggs från samma evidence pack som JSON, inte från separat UI-copy.
4. SchemaVersion och generatedAt behöver explicit regression även om de verkar självklara.

## Rekommenderad Nästa Väg

Det finns ingen Epic 8 i sprintstatus ännu.

Rekommenderade nästa alternativ:

1. Persisted Export History: spara genererade evidence packs och visa tidigare exporter.
2. Product/Security Acceptance: formalisera retention-copy, fälturval och delningsregler.
3. Conformance Modularization: fortsätt minska teknisk risk genom att extrahera framing/build/AI-level conformance.
4. Warning Cleanup: ta bort kända React/Next/webpack-varningar innan exportytan växer mer.

Rekommenderad startpunkt: **Persisted Export History** om auditability är fortsatt prioritet. Välj **Product/Security Acceptance** om målet är att göra exporterna release-klara för externa governance-flöden.
