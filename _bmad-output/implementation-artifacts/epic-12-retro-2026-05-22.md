# Epic 12 Retrospective: Retention Policy Administration

Date: 2026-05-22
Project: AAS-Companion
Epic: Retention Policy Administration
Status: completed

## Sammanfattning

Epic 12 gjorde export retention governance mer läsbar och policy-ready utan att lägga till destruktiv lifecycle-logik. Exporthistoriken visar nu kända archive/download-aktörer som namn eller e-post med actor id som fallback, retention review due/reviewed metadata syns när det finns, och delete/restore har en policy innan implementation.

## Slutförda Stories

- Story 12.1: Resolve Export Audit Actor Display Names
- Story 12.2: Add Retention Review Due Metadata Surfacing
- Story 12.3: Define Policy-Gated Delete/Restore Spec

## Vad Som Fungerade

- Actor labels kunde lösas utan schemaändring: latest download använder relationen till AppUser och archive actor ids löses via separat AppUser-lookup.
- Metadata-only export history kunde bevaras; payload bodies laddas inte.
- Review due display kunde byggas helt ovanpå befintliga `reviewDueAt` och `reviewedAt` fält.
- Delete/restore-policy kunde dokumenteras innan någon riskabel implementation påbörjades.

## Vad Som Var Svårt

- Archive actor är lagrad som fri id-sträng, inte relation, så display name kräver separat lookup.
- Export history är fortsatt tät; retention, acceptance, archive och audit metadata tävlar om samma yta.
- Förfallodatum jämförs vid server-render med aktuell tid, vilket är rätt för UI men bör testas med datum långt i dåtid/framtid för stabilitet.

## Lärdomar

1. Governance readability är en egen kvalitetsegenskap; audit ids räcker för maskiner men inte för operatörer.
2. Fält som redan finns i schema bör synliggöras innan nya lifecycle-tabeller introduceras.
3. Destruktiva actions ska börja som policy/spec, inte som route.
4. Actor id fallback måste bevaras även när display labels finns, eftersom historik ska vara robust mot borttagna användarprofiler.

## Readiness Assessment

Testing and quality: Grönt för riktad regression runt export history actor labels och retention review metadata.

Deployment readiness: Ingen ny DB-migration i Epic 12. Kräver att Epic 8-11-migrationerna finns i målmiljö.

Technical health: Bättre än före Epic 12. Retention governance är mer mänskligt läsbar och har en tydligare policygräns för delete/restore.

Residual risk:

- Delete/restore/legal hold är fortfarande inte implementerat.
- Archive actor saknar FK och historisk referensintegritet; fallback gör UI robust men inte relationellt strikt.
- Export history kan behöva en detaljerad vy innan mer metadata läggs till.
- Full test suite behöver separat cleanup.
